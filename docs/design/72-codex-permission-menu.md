# Codex Chat の権限メニュー

Status: Implementation / Draft（2026-09-15、実機確認待ち）
Memory: mem_1Cf4jdULqRjEXawJPqbxfS

## 目的

入力欄で現在の権限を把握し、同じ会話の次のターンに適用する権限を選ぶ。
ユーザー提示の ChatGPT メニューを参考にする。現在の CodexRuntimePanel の実効値表示を入口にする。
権限は選択中の会話だけに適用し、config.toml は変更しない。

## 表示案

入力欄下部に現在の権限バッジを置き、クリックすると短い説明付きの候補と詳細を開く。

| 候補 | 意味 | 対応案 |
|---|---|---|
| 承認を求める | 読み取りを基本にし、編集やネット利用は承認経路へ | read-only + on-request + user reviewer |
| 標準 | 作業範囲内の編集・コマンド実行、範囲外は承認経路へ | workspace + on-request + user reviewer |
| 代わりに承認 | 承認が必要な操作を自動レビューへ渡す | 明示選択時のみ。承認先と利用可能条件を native で確認 |
| フルアクセス | 制限を外して実行 | danger-full-access + never |
| カスタム | 名前付きプロファイルまたは設定由来の権限 | Codex が返す実在プロファイルを使用 |

プリセットの説明はアクセス範囲と承認方法を説明する。許可ルールが適用されるため「すべての操作で必ずカードが出る」とは表示しない。
「代わりに承認」は reviewer を変更する別機能。初版から候補に含める。
ユーザー裁定（2026-09-15）: 「選択肢には出す。ユーザーが明示的に選んだ場合だけ有効にする」。
メニューを開く、初期表示する、再接続するといった操作では自動レビューを有効化しない。
Codex 側ですでに有効な場合は、その実効状態を正しく表示する。利用できない場合は理由を表示し、選択不可にする。
既知のプリセットと実効値が一致しない場合は無理に分類せず「カスタム」と表示する。
詳細では承認方法、承認先、ネット接続、書き込み範囲、プロファイル名を確認できる。
切断中は最終確認値と明示し、未取得は未確認と表示する。

## 操作と反映

- 対象は選択中の session/thread。別 session やグローバル設定へ書き戻さない。
- 初版の切替は応答・待機入力・ほかの設定操作がないときだけ許可する。
- 変更中は送信と競合する操作を止める。表示はネイティブの実効値通知で確定する。
- フルアクセスは選択時に適用範囲を示し、その場で明示的に確定する。
- 拒否されたら理由を表示する。タイムアウトは未確認として扱い、自動再送しない。
- 再接続・Console からの復帰時も実効値を読み直す。VP の保存値から権限を再適用しない。

## 実装根拠と未解決点

ローカル Codex source の app-server-protocol / core / approval-presets を調査した。

- permissionProfile/list(cwd) は id / description / allowed を返す。組み込みと名前付きプロファイルの候補に使える。
- この一覧だけでは approvalPolicy / approvalsReviewer の組合せの許可を保証しない。requirements と native の更新結果を併せて扱う。
- thread/settings/update は approvalPolicy / approvalsReviewer / permissions を指定できる。permissions と sandboxPolicy は併用不可。
- 更新 API は experimental。既存の mode 切替もこの API を使っている。インストール済みハーネスでの wire 確認が必要。
- CodexRuntime は approvalsReviewer を実効状態に含める。取得できない値を user と推定しない。
- config/read(cwd) の値は実行中 thread の実効値ではない。「設定ファイルに戻す」は再現可能な設定を解決してから提供する。古い workspace 追加パス等を既定プロファイルに置き換えて失わない。
- 名前付きプロファイルの選択と、config.toml の設定全体への復帰は別操作として設計する。

## 検証予定

実効値とバッジの一致、許可されない候補、別 session の通知除外、実行中/Queue 待ちの禁止、更新失敗/未確認、Console 往復、カスタム設定の保持をテストする。
自動レビューは明示選択だけが変更要求を送ること、メニュー表示や再接続では送らないことを検証する。
実際の権限変更は実装後のユーザー操作で検収する。

## 実装記録

- 2026-09-15: GO。初版に「代わりに承認」を含め、明示選択だけで有効化する。
- Codex 0.154.0 の生成 schema と読み取り probe で permissionProfile/list / configRequirements/read を確認。組み込み 3 profile を取得。稼働中の会話への変更要求は送っていない。
- 権限メニューは `codex_permission_menu.rs`。既存の独立権限カード `codex_permissions.rs` とは別の責務。
- メニューを開く操作は候補と管理制約の取得だけ。選択時にも取得し直す。名前付き profile は承認方法・承認先を変更しない。
- 既知の組み込み設定が全軸一致する場合だけ既定ラベルを表示し、追加の writable roots 等がある場合はカスタムとする。
- 変更は Queue と共有する排他領域で行い、RPC と実効値通知を合わせて 25 秒以内に確認する。送信後の失敗は実効値を未確認に戻し、自動再送しない。
- メニューは入力欄の overflow に切られないよう Portal に表示する。
- 2026-09-16: UI 全体 619 テスト、ワークスペース全体のテスト（`env -u SHELL mise run test`）、check / Clippy / typecheck / fmt が通過。権限メニューの実機表示・変更は確認待ち。
- 候補一覧は起動時の固定ディレクトリではなく、会話の実効 cwd で取得する。Queue の未更新状態でも変更を拒否し、候補取得後にも会話の状態を確認する。

### やってはいけないこと

- メニュー表示・初期表示・再接続を理由に権限更新を送らない。
- permissionProfile/list の allowed だけで承認方法・承認先の組合せまで許可されたと判断しない。
- 更新の受理応答だけで成功表示しない。以前のキャッシュ一致も更新完了の証拠にしない。
- 組み込み workspace の選択を「config.toml に戻す」と表示しない。
