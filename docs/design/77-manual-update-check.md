## 操作

設定 → メンテナンス → アップデートに「今すぐ確認」を常設する。
未確認を「最新版」と扱わず、確認中・最新版・更新あり・確認失敗を区別する。
確認中と更新適用中は確認ボタンを無効化し、失敗後は同じボタンで再試行できる。
更新ありの場合は版を示した更新ボタンを出す。確認だけではダウンロード、適用、再起動を行わない。
更新操作は既存の `update:apply` とネイティブ確認ダイアログを使う。

## 経路

`update:check` IPC → app の非同期 HTTP → daemon の既存 `/api/update/check` → GitHub Releases。
結果は AppEvent / `update:check_result` で設定へ戻す。通信全体は20秒でタイムアウトする。
配布元・認証・バージョン比較は既存の UpdateCapability に集約する。
既存の更新 API を再利用するため、この read-only 確認では HTTP を利用する。
lane / repo の control plane は引き続き Unison のまま。

手動確認は `force=true&current_version=<GUIの版>` を送り、5分キャッシュを使わず取得する。
daemon 自身の版ではなく、開いている GUI の版と比較する。通常の確認 API は従来のキャッシュを維持。
`fresh_check` がない旧 daemon の応答は手動確認成功とせず、更新・再起動が必要な旨を返す。
この機能を反映するには GUI と daemon の両方が本変更を含む必要がある。

## 検証

- DOM: 未確認、確認中の連打、更新あり、明示的な適用、失敗、再試行、最新版。
- Rust: 確認 IPC が適用・再起動を要求しないこと。ローカルHTTPサーバーで要求URLと応答処理を確認。
- 実機: 「今すぐ確認」→結果、ネットワーク切断時のエラーと再試行、更新ありのボタン表示。
  実際の更新は別途ユーザーが実行する。

## やってはいけない

- 未取得・通信失敗を「最新版です」に落とさない。
- 更新確認に伴ってアプリや daemon を再起動しない。
- 古い daemon のキャッシュ応答を「今確認した」結果として表示しない。
